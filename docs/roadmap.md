# 湖's Takeaway 六步总路线

## 1. Demo 收尾（本次已完成）

- 紧急客服请求完整状态机、去重、取消与关闭。
- 一次性授权的用户放弃、客服撤销和业务状态自动失效。
- 柜体/柜格维修工单、现场机械开锁记录、四项检查、自检和受控恢复。
- 页面错误提示、调试数据重置、审计动作名称与 Mock/云端边界收口。
- 静态检查和跨角色、多柜体端到端业务冒烟测试。

## 2. 微信云开发（不依赖硬件的软件部分已完成）

当前进度：真实微信云环境 `cloud1-takeaway-d9fcdc9a85c2ebda` 已启用，云函数、集合、服务端角色权限、当前协议版本门禁、核心组合索引及主要业务流程已经部署并验证。用户存取、个人历史、反馈、客服授权、紧急请求、柜体管理、实体柜体遥测、维修工单和分权限审计日志均以云端为业务事实来源；HM-10 + STM32 实体 BLE、电子锁反馈、维修自检和恢复链已经真机验证。

- 微信登录、云数据库、云函数、服务端角色和隐私协议版本。
- Cabinet、Locker、DepositRecord、Feedback、OperationLog、EmergencySupportRequest、EmergencyUnlockAuthorization、MaintenanceWorkOrder 上云。
- 正式取餐码和一次性开锁授权在云端生成与验证。

## 3. BLE 与硬件控制器固件（当前为 HM-10 + STM32 原型）

- 已完成 HM-10 发现、连接、FFE0/FFE1、Notify、`@IDENTIFY`、`@OPEN`、`@STATUS` 和实体柜体身份校验。
- 已完成电子锁蓝白反馈的 `OPEN/CLOSED` 状态、自检、遥测同步和维修恢复链真机验证；当前不使用独立门磁。
- 后续仍需完成正式签名授权、防重放、低电量/电池遥测协议和发布级控制器安全设计。

## 4. 实体结构

- 完成柜体、柜格、门体、锁舌、机械应急开锁、电源和维护空间设计。
- 确定电子锁、反馈线路、驱动、电池、控制器和线束安装方案；当前柜门状态由电子锁蓝白反馈提供，不单独增加门磁。
- 进行强度、安全、散热、防水、防夹和现场可维修性验证。

## 5. 软硬件联调

- 用真实柜体完成扫码、登录、云端授权、手机 BLE、STM32、电子锁和反馈闭环。
- 校准连续三次真实开锁失败报修阈值、电量告警、自检与维修恢复流程。
- 做断网、低电、卡锁、传感器异常和机械应急演练。

## 6. 发布验收

- 隐私合规、权限与审计安全检查。
- 多柜体部署、二维码生成、运维后台和客服/维修 SOP。
- 真机兼容、压力、容灾、现场试运行和正式发布验收。
